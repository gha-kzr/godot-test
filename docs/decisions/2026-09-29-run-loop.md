# Run loop: tower and stages (milestone 4) — decisions

Milestone 4 of [`docs/roadmap.md`](../roadmap.md). Builds on the progression record ([`2026-09-28-progression.md`](2026-09-28-progression.md): levels, XP and items persist on death, only the run resets; saving between battles) and the design tools record ([`2026-09-29-design-tools.md`](2026-09-29-design-tools.md): enemies with levels, presets, encounters, balance lab). Answers the roadmap's open questions on run length, difficulty scaling, party, stalemates and run saving.

| Decision | Choice | Why | Revisit when |
|---|---|---|---|
| Architecture | Plain-data run model (`RunState`, saved in the profile) + pure `RunDirector` + deterministic `FloorGenerator` / `MapGenerator`; the `Game` root only swaps screens | Same split as the rest (rules as plain data, display on top); testable headless; untouched by the M5 UI redo | — |
| Modes | Two: a list of **stages** and an **infinite tower**. Clearing a stage raises the tower's **floor cap** and unlocks a new **starting floor** | Progress through stages gives the tower's depth meaning; later starting floors avoid replaying floor 1 forever | — |
| Tower | A straight line of fights until the party falls or clears the capped floor. **Elites** on floors ending in 5 (5, 15, 25…), **bosses** on multiples of 10 (10, 20, 30…). **Best depth** recorded | The requested structure; milestones every 5 floors | — |
| Tower cap | Clearing the capped floor ends the run as a **success**; going higher needs the next stage. If a stage is too hard, the player improves the party in the tower | Clear end instead of an invisible wall; a reason to do stages | — |
| Stages | A stage is **one battle** (generated, deterministic). 3 stages to start: stage 1 plays like a tower floor-10 boss fight; clearing stage *k* raises the tower cap to 10 × (k+1) and unlocks starting at floor 10k + 1. The cap starts at 10 | Milestones beaten once | more stages / hand-made stages are wanted |
| After a boss | Pick **one of 3 boons, or a full heal instead**; then **continue** or **leave** the tower (the run ends as a success at that depth) | A real trade-off; attrition stays meaningful without a free reset | playtests |
| Boons | Run-only bonuses, like a **hidden rune for the whole team**: `BoonData` = stat modifiers applied to every hero until the run ends. Tiers by boss floor (10: minor, e.g. +8 Power; 20: major, e.g. +20 Power or +1 MP; 30+: epic, e.g. +1 AP) — **all numbers are data**, adjustable after playtests | Reuses the rune / level modifier machinery; simple | playtests |
| HP during a run | HP carries over between battles; after each won battle, every hero below 25 % (fallen ones included: revived) is raised to **25 %** of max HP | Attrition is the core tension; nobody is left unplayable | playtests |
| Difficulty | From the **floor only**, never the party's level (so a best depth means something). A data curve by floor band: enemy level, enemy count (1 → 3), which enemy types appear; elite floors use the elite preset, boss floors a boss plus escorts; tuned in the balance lab | Depth is the score; the first floors are easy for a fresh party | playtests |
| Determinism | Floor N (and stage N) always has the **same map and enemies** — seeded from its number — so floor 1 is identical for everyone and every run of a floor gives the same XP. **Battle dice and loot stay random** | A known, fair challenge; retries aren't memorization | — |
| Starting floor | A run may start at any unlocked starting floor (1, 11, 21…), with no bonus for skipped floors | Heroes keep levels and loot anyway | — |
| Maps | **Procedurally generated** from the floor's seed: heights, obstacles, holes, 3 player and 1–3 enemy spawns, always checked for connectivity; boss floors get larger, more open maps. The map painter stays deferred | Endless variety; deterministic per floor | hand-made set pieces are wanted |
| Stalemate safety net | From **round 40**, each party unit loses **10 % of its max HP** every round (the party only), with a warning banner | A stalled battle always ends (in a defeat); normal battles never get there | — |
| Party | Knight, Mage and Ranger, **all playable from the start**, always all three (maps have 3 player spawns). Team building from level 1 with more classes is planned later | The Ranger was locked only for an unlock that is dropped | team building is designed |
| Unlocks | None for now (the Ranger's unlock is dropped) | Replaced later by team creation | team building |
| Run saving | The run (mode, floor, party HP, boons, best depth, unlocked caps and starts) is saved **between floors**, never mid-fight; quitting resumes at the next floor | Standard for the genre; builds on the profile save | — |
| Menus (first version) | The party screen is the hub: a **Tower** button (starting floor among the unlocked ones, best depth shown) and a **Stages** list (locked / available / cleared). Between floors: rewards and **Next floor**, the boss choice after bosses | Minimal UI to play the loop; **revamped in M5** | UI polish (M5) |
| HUD | Shows the floor number in tower fights and the round-40 warning | Players know where they are | M5 |

## Open / deferred
- "Leave the tower" has no extra payoff yet (death keeps everything); revisit if run-only rewards become valuable.
- Hand-made stages and a map painter — later, if generated stages feel samey.
- Team creation from level 1 with more classes — after this milestone.
