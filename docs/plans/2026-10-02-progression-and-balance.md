# Milestone 6c: progression and balance quick wins — plan

Decisions: [`docs/decisions/2026-10-02-progression-and-balance.md`](../decisions/2026-10-02-progression-and-balance.md). Branch `milestone-6c`; one commit per task; tests and mutation checks; `godot-code-review` at the end.

1. **Web audio**: stream playback on web (project setting); republish, owner tests.
2. **Pin on attack**: in `BattleController.click_cell`, pin only when the click does nothing else (no cast, move or placement). Pattern: the click's outcome decides the side effect. Tests.
3. **Level cap 100**: `level_cap`, thresholds generated by the curve formula (`ProgressionConfig` computes beyond the authored array), validation updated; hub and run screens already show levels (check at level 100 widths). Growth rule for HP/Power per level past the authored rewards (`HeroData` fields), +1 MP at 15, +1 AP at 20 (`LevelReward`-like generated rewards through `HeroData.reward_for`). Tests: thresholds match the authored ones for 1–10, rewards past 10, save compatibility.
4. **Balance pass** (light, with a script and the balance lab): compute XP per floor and the hero level reached by floor; calibrate the XP curve factor and the bands' `enemy_level` to the pace targets; set enemy per-level growth so a level N enemy is ~90 % of a level N hero; floors from 10 with 3 enemies, more deeper; Knight HP growth + 10 % physical resistance; area spells' damage per target; stage `difficulty_floor = unlocks_cap − 5`. Record the tables in the decision record.
5. **Missing sounds**: `cast_sound` on `SpellData` + damage-type default, death and victory sounds; a sampler for the owner to choose; credits.
6. **Docs and review**: README (cap, growth, sounds, web audio), roadmap, backlog (resolved notes), review.
