# Screens (milestone 5b) — implementation plan

Decisions: [`docs/decisions/2026-09-30-screens.md`](../decisions/2026-09-30-screens.md) (and [`2026-09-30-ui-revamp.md`](../decisions/2026-09-30-ui-revamp.md)). Roadmap: [`docs/roadmap.md`](../roadmap.md), milestone 5 (5b: screens).
Architecture: **A — `Game` stays the router, plus a `Settings` model passed down.** Screens are scenes that take plain data and signal choices up; `Game` applies them. No new autoloads. Built for desktop and web first, then maybe Android, later gamepad: no hover-only UI, anchored layouts, platform calls guarded in one place (`SettingsApplier`).

## Design summary

### Scene tree
```
Game (Node): Profile + SaveStore, Settings + SettingsStore, Hints
└── screen (one child)
    ├── TitleScreen        Play · Settings · Quit (hidden on web)
    ├── SettingsScreen     Display · Controls (rebinding) · Game (reset save, show hints) · Credits · Back
    ├── PartyScreen        TopBar (Title button, summary) · HeroTabs | HeroPanel | RuneStash · DestinationBar
    ├── RunScreen          Header · FloorStrip · PartyHpRow · Report · Choices · Buttons
    └── BattleController   unchanged; right click over the HUD cancels aiming; first_battle hint
```

### Signals and flow
- Boot: load settings → apply → title. `play_pressed` → `next_step()` (hub, or the saved run); `settings_pressed` → settings; `quit_pressed` → quit (not on web); the hub's `menu_pressed` → title.
- Settings: `changed(settings)` → `Game` applies and saves; `reset_save_confirmed` → fresh `Profile` (settings kept); `back_pressed` → title.
- Hub components re-emit through `PartyScreen`: `hero_selected`, `equip_requested`, `unequip_requested`, `tower_pressed`, `stage_pressed`, `continue_pressed`, `abandon_pressed`. `Game` remembers the selected hero.
- Esc = back on every non-root screen (`Screen` base, `ui_cancel`); during a key capture Esc cancels the capture.

### Data
- `Settings` (RefCounted): `window_mode`, `ui_scale`, `bindings` (action → physical keycode), `dismissed_hints`. `SettingsStore`: `user://settings.cfg` (`ConfigFile`, atomic write, corrupt → defaults). `SettingsApplier`: scale, window mode (not on mobile), `InputMap` (defaults snapshotted for reset).
- Spell keys become InputMap actions `spell_1..9` (`SpellBar` uses an action shortcut). Rebindable: spell 1–5, end turn, camera left / right, toggle view, show order; right click and Esc are fixed.
- `Hints` wraps `dismissed_hints` (`should_show`, `dismiss`, `reset`); texts in one constant; `HintCard` scene.
- Credits read `res://CREDITS.md` (the web export must include it).

## Tasks

Each task ends with: `--check-only` on edited scripts, headless tests green (plus mutation checks on new tests), `tools/fill_uid_refs.gd` after CLI-made resources, a render check (`--write-movie`) for visual changes, a commit of explicit paths.

- [x] **Task 1: Settings foundation** — `Settings`, `SettingsStore`, `SettingsApplier`; spell actions `spell_1..9` in the InputMap and `SpellBar`; `Game` loads and applies settings on boot.
  Pattern: `ConfigFile` for preferences, runtime `InputMap` remap, `Window.content_scale_factor`.
  Done: `scripts/progression/settings.gd` (`Settings`: window mode, UI scale, bindings, dismissed hints; `REBINDABLE` actions and labels), `settings_store.gd` (`ConfigFile`, atomic write, bad values fall back one by one), `settings_applier.gd` (scale, window mode, `InputMap` remap with captured defaults, `set_binding` refusing a key another action uses, `key_text` for the player's layout). `spell_1..9` actions in `project.godot`; `SpellBar` slots use action shortcuts and show the bound key. `Game` has `settings` / `settings_path` and applies them on boot.
- [x] **Task 2: Screen base and title** — `Screen` base (Esc back, `focus_first`), `TitleScreen`, boot flow in `Game`, a Title button on the hub, Quit hidden on web.
  Pattern: signals up, calls down through `Game`.
  Done: `scripts/game/screen.gd` (`Screen`: Esc → `back_pressed` unless `back_enabled`, `focus_first()`), `title_screen.gd` / `scenes/game/title_screen.tscn` (Play, Settings, Quit; Quit hidden on web), `Game.TITLE`, `Game.show_title()`; the game boots on the title, Play opens the hub (Esc on the hub returns to the title); `Game` focuses each new `Screen`. The Settings button is wired in Task 3; the hub's Title button arrives with its restyle (Task 4).
- [x] **Task 3: Settings screen** — display, controls (capture, conflicts, reset keys), game (two-step reset save, show hints again), credits; `Game` wiring.
  Pattern: a capture state consuming the next key in `_input` and marking it handled.
  Done: `scripts/game/settings_screen.gd` / `scenes/game/settings_screen.tscn` (one scrolling page: Display, Controls, Game, Credits; Back). Key capture runs in `_input` and marks the key handled (Esc cancels the capture instead of going back, modifiers alone are ignored, a taken key is refused with a message); reset save asks "Really reset?" inline with No focused first; "Show hints again" clears `dismissed_hints`; credits come from `CREDITS.md` (table rows as lines, fallback text). `Game.show_settings()` applies and saves on every `changed`, and a confirmed reset creates a fresh profile and keeps the settings. The number row shows as digits on any layout.
- [x] **Task 4: Hub restyle** — `HeroTabs`, `HeroPanel`, `RuneStash`, `DestinationBar` behind the same `PartyScreen` signals; selected hero kept across screens; focus neighbours.
  Pattern: component scenes with plain-data inputs.
  Done: `scenes/game/hub/` + `scripts/game/hub/`: `HeroTabs` (`set_selected` keeps focus), `HeroPanel` (stats, spells as focusable buttons whose click shows the description, 6 rune slots), `RuneStash` (scroll follows focus), `DestinationBar` (run in progress, or tower picker and stages), `HubStyle` helpers; `PartyScreen` is the facade (same signals, plus `hero_selected`; a Title button and Esc go back). `Game` keeps the selected hero across screens. Every hub button takes focus (Godot's geometric focus navigation, no hand-set neighbours needed), and `PartyScreen` refocuses the rebuilt button with the same name after a change.
- [x] **Task 5: Run screen** — `FloorStrip`, `PartyHpRow`, restyled report and choices, new spells in the level-up summary; focus.
  Pattern: component scenes with plain-data inputs.
  Done: `scenes/game/run/` + `scripts/game/run/`: `FloorStrip` (ten floors from four cleared ones back; cleared tinted, next highlighted, `E` on elite floors, a skull on boss floors; hidden for stage runs), `PartyHpRow` (name · level, HP bar, "hp / max" from `UnitInfo`); `RunScreen` is now a `Screen` without Esc (leaving stays an explicit button), shows boons on a line, lists the spells a level-up unlocks ("Knight reached level 3 and learned Whirlwind."), and its buttons take focus.
- [x] **Task 6: Hints** — `Hints`, `HintCard`, the `hub_intro` and `first_battle` hints, "Show hints again".
  Pattern: a thin helper over persisted flags; one removable component.
  Done: `scripts/progression/hints.gd` (`Hints`: texts, `should_show` / `dismiss` / `reset` over `Settings.dismissed_hints`) and `scripts/game/hint_card.gd` / `scenes/game/hint_card.tscn` (`HintCard`, a "Got it" card). `hub_intro` shows on the hub (bottom right), `first_battle` on the battle HUD (top right; Enter also dismisses, the button can't take focus because Space ends the turn). `Game` owns the `Hints`, shows them only if not dismissed and saves the settings on dismissal; "Show hints again" clears them. Removing hints = deleting `Hints`, `HintCard` and the `show_hint` calls.
- [x] **Task 7: Small UX items** — right click over the HUD cancels aiming; self-buff wording in `ApplyStatusEffect.describe()`.
  Pattern: `_input` with `gui_get_hovered_control`; data-driven description text.
  Done: `BattleController._input` cancels aiming on a right click over a HUD control (the control would otherwise eat the click); `ApplyStatusEffect.describe()` says "for your next 2 turns" for a status put on the caster (a self-buff doesn't count the turn it is cast in), "for 2 turns" otherwise. The hub Continue / level-up spells / selected-hero items were done in tasks 4 and 5.
