# Run loop: tower and stages (milestone 4) — implementation plan

Decisions: [`docs/decisions/2026-09-29-run-loop.md`](../decisions/2026-09-29-run-loop.md). Roadmap: [`docs/roadmap.md`](../roadmap.md), milestone 4.
Architecture: **A — plain-data run model + run director + deterministic generator**. The run's rules live in plain classes (`RunState`, `RunDirector`, `FloorGenerator`, `MapGenerator`) with no nodes; the `Game` root only swaps screens and asks the director what's next.

## Design summary

### Data (`scripts/data/`, `data/tower/`)
- `TowerConfig`: `seed_salt`, `initial_cap` (10), `bands: Array[FloorBand]`, normal / elite / boss presets, `boons: Array[BoonData]`, `boss_tier_floors` ([10, 20, 30]), `map_settings: MapGenSettings`, `sudden_death_round` (40), `sudden_death_percent` (10), `stages: Array[StageData]`.
- `FloorBand`: `from_floor`, `enemy_level`, `levels_per_floor`, `min_enemies`, `max_enemies`, `enemy_pool`, `boss_pool`.
- `BoonData`: `display_name`, `tier`, `modifiers`. `StageData`: `display_name`, `seed`, `difficulty_floor`, `unlocks_cap`, `unlocks_start_floor`.
- `MapGenSettings`: sizes (normal / boss), obstacle and hole density, plateau count, max height.

### Generation (`scripts/run/`)
- `FloorGenerator.encounter(config, floor)` / `stage_encounter(config, stage)`: deterministic (RNG seeded from `seed_salt` + floor or the stage's seed); elite on floors ending in 5, boss + escorts on multiples of 10.
- `MapGenerator.generate(rng, settings, enemy_count, is_boss) -> MapData`: plateaus, obstacles, holes, 3 player spawns on one edge and the enemy spawns on the opposite edge; connectivity checked both ways, retried from the same RNG stream.

### Run rules (`scripts/run/`)
- `RunState`: mode, stage, floor, start floor, hero HP, boons, pending boss offer.
- `Profile` (save version 4): `best_depth`, `cleared_stages`, `run`; tower cap and starting floors derived from cleared stages.
- `RunDirector`: `start_tower`, `start_stage`, `battle_setup` (encounter, party units with level / rune / boon modifiers, starting HP, sudden-death settings), `apply_result` (rewards, HP carry-over with the 25 % floor, best depth, cap → success, boss → offer, stage → cleared, loss → run over), `apply_boss_choice` (boon or full heal; continue or leave). Returns reports for the screens.

### Battle changes
- `BattleState.create(..., player_hp)`: heroes start with their carried HP.
- `Battle.sudden_death_round` / `sudden_death_percent`: from that round, each party unit loses that percent of its max HP at its turn start (a `DamageDealt`, then the normal death check).
- Party of three: roster starts with all three heroes unlocked and in the party.

### Screens (first version, revamped in M5)
- Party screen = hub: **Tower** (starting floor among the unlocked ones, best depth), **Stages** (locked / available / cleared), **Continue run** when one is saved.
- Between floors: the report (rewards, level-ups, HP), **Next floor**; after a boss, the 3 boons or a full heal, then **Continue** / **Leave**; at the end, the run summary and **Back to the party**.
- HUD: the floor (or stage) name; a banner when sudden death starts.
- Design panel: **Export floor N** as an encounter `.tres`.

## Tasks

Each task ends with: `--check-only` on edited scripts, headless tests green (plus mutation checks on new tests), `tools/fill_uid_refs.gd` after CLI-made resources, a commit of explicit paths.

- [x] **Task 1: Battle changes** — starting HP; sudden death. (The party of three moved to Task 5, with the game flow that needs 3 spawns.)
  Pattern: rules layer only (Battle / BattleState), events for every change.
- [x] **Task 2: Tower data** — `TowerConfig`, `FloorBand`, `BoonData`, `StageData`, `MapGenSettings`; `data/tower/tower.tres` with bands, boons (3 tiers) and 3 stages.
  Pattern: data-only resources with validation.
- [x] **Task 3: Map and floor generators** — deterministic generation; floors 1–100 valid.
  Pattern: seeded `RandomNumberGenerator` streams; generate-and-validate with deterministic retries.
- [x] **Task 4: Run state, director, profile v4** — run rules and saving.
  Pattern: plain-data model + pure director returning reports (command / result).
- [x] **Task 5: Game flow and screens** — hub, between-floors and boss-choice screens, battles from the director, HUD floor label and sudden-death banner, resume.
  Pattern: root scene swapping child screens; signals up, calls down.
- [x] **Task 6: Export floor tool and difficulty tuning** — Design panel export; tune bands so the first floors are easy (lab checks).
  Pattern: data tuning with the balance lab.
  Done: **Export floor** saves a floor's generated encounter (map inside) in `data/encounters/`; the lab takes 3 heroes (the slice map got a third player spawn) and gained **Tower runs** (`TowerSim`: whole runs through `RunDirector`, AI vs AI, found runes auto-equipped, first boon picked), reporting depths and losses per floor. Bands after one light pass (AI-played party, which is weaker than a player): floors 1–3 never lost; a fresh party's first run ends around floor 4; floor 10's boss needs a few runs (levels); with level-10 heroes and runes, floors 11–19 are easy and floor 20's boss takes 3–6 runs. Band 5: level 1 (+0.25 / floor), 2 enemies; band 10: level 2 (+0.3), 2 enemies; band 20: level 4 (+0.3), 3 enemies; band 30: level 9 (+0.5). Further tuning is left to playtests, with the lab.
- [x] **Task 7: Review and polish** — `godot-code-review` subagent; fixes; README; docs.
  Done (review fixes): a pending boss choice is an explicit flag, so a saved offer whose boon files are gone still offers the heal instead of replaying the boss; duplicate boons can't hang the offer (distinct pool, validation counts distinct boons); malformed run fields load with defaults instead of a script error; a saved run is dropped when its party can't be restored exactly (its HP is per slot); the tower sim cancels mid-battle (closing the panel no longer waits for a whole run); the Game, Export floor and the floor generator refuse an invalid tower with its errors instead of crashing.
  Deferred from the review: a lasting HUD tag for sudden death (the banner shows once, from the live round); carried HP stored as absolute values (a level-up or +HP boon leaves undamaged heroes below full); floor 10 is the first cap, so boons first appear after stage 1 — confirm in playtests; `start_tower` / `start_stage` overwriting a run (only the hub prevents it); a golden test pinning floor N's content across engine upgrades (`hash()`); a stage run resuming after its stage left `tower.stages`; the AI ignoring sudden-death pressure → M5 or when they matter.
