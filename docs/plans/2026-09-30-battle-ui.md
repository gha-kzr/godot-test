# Battle UI revamp (milestone 5a) — implementation plan

Decisions: [`docs/decisions/2026-09-30-ui-revamp.md`](../decisions/2026-09-30-ui-revamp.md). Roadmap: [`docs/roadmap.md`](../roadmap.md), milestone 5 (5a: battle).
Architecture: **A — HUD component scenes + a pure preview class**. `Hud` stays the controller's one entry point and forwards to component scenes (`TurnTimeline`, `UnitCard`, `SpellBar`, `PromptLine`, `OrderOverlay`) that take plain info values and signal clicks up; world-space display (status icons, damage badges, path cost) goes through `UnitsView` / `BoardView`; numbers come from `DamagePreview` (the battle's own formula, read-only); a cartoon `Theme` styles everything.

## Design summary

### Scene tree
```
Hud (CanvasLayer, theme res://ui/theme.tres)
└── Root
    ├── TopBar: RoundLabel, TurnTimeline (next 5, "All (Tab)"), PromptLine
    ├── ActiveCard (UnitCard, bottom left) · InspectCard (UnitCard, right; ✕ when pinned)
    ├── SpellBar (icons, AP cost, 1–9) · Actions (view toggle, End turn — pulses when nothing is left)
    ├── Banner · OrderOverlay (full order, Tab / Esc) · ResultPanel
```
3D: `UnitView` status icon row (`Sprite3D` + turns `Label3D`) and a preview badge; `BoardView` path cost `Label3D` and climb marks.

### Signals and flow
- `chip_hovered(unit_id)` / `chip_unhovered` → highlight the unit's cell; `chip_pressed(unit_id)` → camera focus; `card_closed` → unpin; `spell_selected(index)` (kept); `order_toggled` (Tab, action `show_order`).
- Pinning: clicking a unit pins its card (on a target cell, the click still casts); clicking another unit pins that one; ✕ or Esc unpins.
- Event-driven HUD: a `HudModel` keeps displayed `UnitInfo`s updated per played event (`hp_after`, `mp_spent`, `ap_spent`, status turns, `TurnStarted` AP / MP, deaths); the controller re-syncs from the state after each playback. Events gain `StatusTicked.turns_left` and `TurnStarted.ap` / `mp`.
- `DamagePreview.for_cast(state, caster_id, spell, target)` → entries (unit, min / max damage or heal, can kill, statuses) → `UnitsView` badges while aiming.
- Path cost: `reach.cost_to(cell)` and climbing steps → `BoardView` label and marks.
- `PromptLine` text from the controller state; End turn pulses when no reachable cell and no affordable spell.

### Data
- `SpellData.icon`, `StatusData.icon` (`Texture2D`, optional; fallback icons tinted by damage type / status color); `ui/icons/*.svg` from game-icons.net; `CREDITS.md`.
- `ui/theme.tres`: cartoon style (rounded panels and buttons, bright accents, outlined labels).
- `project.godot` application name "Tower Tactics" (placeholder).

## Tasks

Each task ends with: `--check-only` on edited scripts, headless tests green (plus mutation checks on new tests), `tools/fill_uid_refs.gd` after CLI-made resources, a render check (`--write-movie`) for visual changes, a commit of explicit paths.

- [x] **Task 1: Theme, icons, name** — `ui/theme.tres`, game-icons SVGs for every spell and status, `icon` fields with fallbacks, `CREDITS.md`, the placeholder name.
  Pattern: a project-wide `Theme` resource (type variations for panels / chips); icons as imported SVG `Texture2D` referenced from data resources.
  Done: `ui/theme.tres`, built by `tools/build_theme.gd` (drawn rounded boxes, Fredoka semi-bold, outlined labels; HUD type variations `Chip`, `ChipActive`, `SlotButton`, `SelectedSlotButton`, `CloseButton`, `HeaderLabel`, `SmallLabel`, `PromptLabel`), set project-wide (`gui/theme/custom`). A bought UI pack (Vector UI Pack, dobo_ui) was tried as a skin and dropped: the drawn theme looked better, and the pack's license kept it out of the public repository. Spells and statuses have `icon` (`display_icon()` falls back to defaults); third-party files are listed in `CREDITS.md`. The placeholder name moves to 5b's title screen: changing `config/name` would move the save folder.
- [x] **Task 2: HUD components** — split `Hud` into `TurnTimeline` (5 chips with portraits and HP bars, hover / click), `OrderOverlay` (Tab), `UnitCard` (active + inspect, pin with ✕ / Esc), `SpellBar` (icons); behavior otherwise unchanged.
  Playtest feedback to address: chips were packed and unreadable ("Archer Lv 1 28": the level and the bare HP number run together) — chips show the name and an HP bar only (the HP number and level in the card and the overlay); the timeline showed every unit — cap at 5; the active card touched the spell bar (and 5 spells are coming) — a narrower, taller card with a gap, square icon slots; heroes' levels showed nowhere in battle — the cards show "Knight · Lv 7" (the controller passes the party's levels); spell tooltips were messy — hovering a spell slot shows a **spell details panel at a fixed place above the spell bar** (name, AP, range, area, effects) instead of a tooltip.
  Pattern: component scenes with plain-data inputs; signals up, calls down through a facade (`Hud`).
  Done: `scenes/battle/hud/` + `scripts/view/hud/`: `TurnTimeline` (5 chips: name + HP bar, hover / click → `chip_hovered` / `chip_pressed`, "All (Tab)" button), `OrderOverlay` (every unit with level, HP, status icons; `show_order` action = Tab, Esc or a click outside closes), `UnitCard` (active card narrower and taller, gap from the bar; inspect card with spell list and ✕ when pinned), `SpellBar` (square icon slots with AP cost and key, details panel at a fixed place above the slots; also shown when hovering a spell on the inspect card). `UnitInfo` / `StatusInfo` are now standalone classes (with `unit_id`, `level`, status icon); `Hud` forwards to the components. The controller pins on click (`pin` / `unpin`; Esc closes the overlay, then stops aiming, then unpins), focuses the camera on a clicked chip, treats a hovered chip's unit as the hovered cell, and gets the heroes' levels through `setup(levels)` (`RunDirector.Setup.levels`). `SelectedSlotButton` gained `pressed` styles in `build_theme.gd`.
- [x] **Task 3: Event-driven HUD** — `HudModel` applying events; `StatusTicked.turns_left`, `TurnStarted.ap` / `mp`; per-event redraw, re-sync after playback.
  Pattern: a view model updated from the event stream (the display replays events; the state stays the source of truth).
  Done: `scripts/view/hud_model.gd` (`HudModel`): infos per unit, turn order, round and current unit, updated by `apply(event)` (HP, AP / MP spent, status applied / ticked / expired, per-turn countdown on `TurnEnded`, deaths) and rebuilt `from_state` after each playback. `TurnStarted` carries `ap` / `mp`, `StatusTicked` carries `turns_left`. The controller feeds the HUD (order, cards, spell bar AP via `Hud.set_spell_ap`) from the model on every played event. A test replays a whole AI battle with poison / haste / slow and checks the model against the state after every action.
- [x] **Task 4: Status icons over units** — `UnitView` icon row with turn counts, replacing text tags.
  Pattern: `Sprite3D` / `Label3D` billboards, pooled per status.
  Done: `UnitView` keeps one `Tag` node per status (`Icon` `Sprite3D` from `display_icon()`, tinted with the status color, sized in world units, and a `Turns` `Label3D`), in a row that faces the camera; applied / ticked (pulse) / expired (fade) as before. `status_tag_texts()` became `status_turns_texts()` and `status_icon_textures()`; the status's `short_label` is no longer drawn over units.
- [x] **Task 5: Damage preview** — `DamagePreview` (min / max per effect, target filters, resistances, Power, kill check, statuses) and unit badges while aiming.
  Pattern: a pure query on the rules layer mirroring `apply()` without mutation (like `EnemyAI`'s simulation, but exact bounds instead of averages).
  Done: `scripts/battle/damage_preview.gd` (`DamagePreview.for_cast` → `Entry`: min / max damage and heal after caps, `can_kill`, statuses, `amount_text()`). It plays the real `CastSpell.apply` on two clones with `BattleState.roll_bound` LOWEST / HIGHEST, so it is the battle's own formula (a test casts 60 seeds and checks every real roll lands inside and both bounds occur). `UnitView.show_preview` draws a camera-facing badge (amount, skull, status icons); `UnitsView.show_previews` / `clear_previews`; the controller shows them for the hovered target while aiming and clears them on any state change.
- [x] **Task 6: Path cost, prompt line, End turn pulse** — MP label and climb marks on the hovered path; `PromptLine`; the pulse.
  Pattern: `Label3D` overlays; a looping `Tween` started / killed with the state.
  Done: `BoardView.show_path_cost` / `clear_path_cost` (a "n MP" `Label3D` over the destination, "+n" over each climbing step from `Movement.climbing_steps`); the prompt is a `PromptLabel` in the Hud's top bar (`Hud.set_prompt`, text from `BattleController._prompt_text()` per state, replacing the placement banner); `Hud.set_end_turn_pulse` runs a looping `Tween` on the End turn button while `_nothing_left_to_do()` (no reachable cell and no affordable spell), killed on any other state.
- [x] **Task 7: Review and polish** — `godot-code-review` subagent; fixes; README (controls: Tab, pinning; preview); docs.
  Done: a `godot-code-review` subagent reviewed `2175e5f..HEAD`; fixed (each with a test): a hovered timeline chip released when the row is rebuilt, Space / 1-9 locked while the order overlay is open, `HudModel` order after the acting unit dies, zero-amount hits left out of previews (and the badge tint), wheel ticks no longer close the overlay, overlay rows built on open. Not fixed: hover maps through the final state while events play (unit-by-cell during a move animation); harmless at this scale. README updated (controls, preview, path cost, status icons).
