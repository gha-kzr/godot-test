# Milestone 6b: feel and language — plan

Decisions: [`docs/decisions/2026-10-02-feel-and-language.md`](../decisions/2026-10-02-feel-and-language.md). Branch `milestone-6b`; one commit per task; tests, `--check-only`, a render where something is visible; `godot-code-review` at the end; `main` only on the owner's word.

## Tasks

### A. Localization
1. **Foundation.** `locale/en.po`-less setup: Godot's `TranslationServer` with gettext **`locale/fr.po`** (English source text as msgid, no `en.po`), registered in `project.godot` (`internationalization/locale/translations`); fallback locale `en`. A `Localization` helper (RefCounted, static): supported locales, `initial_locale()` (OS language if supported, else `en`), `apply(locale)`. Check the UI font (Fredoka) covers French accents with `Font.has_char`; add a credited fallback font if not. Pattern: Godot internationalization (gettext, `tr()`, `auto_translate_mode`).
2. **Language setting.** `Settings.language` (`""` = automatic), saved in `settings.cfg` by `SettingsStore`, applied at start and live on change by `SettingsApplier`; a Language row (Automatic / English / Français) in the settings screen, whose own labels are not translated (each language in its own name). Test: store round trip, automatic resolution, live switch.
3. **Route screens and HUD through `tr()`.** Title, settings, hub (party screen and components), run screen, hint cards, battle HUD, result screen, boss choice. Controls keep `auto_translate_mode` inherited; strings assembled in code use `tr()` with `%s` / `%d` placeholders (one template, never fragments); counts use `tr_n()`; `tr(text, context)` for words with several meanings. Pattern: placeholder templates, plural forms.
4. **Content text.** `display_name` of heroes, enemies, spells, runes, boons, statuses, stages, damage types, difficulty tags go through `tr()` where they are shown. `describe()` methods (effects, statuses, runes, boons, level rewards, spells) use translated templates. Test: no `describe()` output contains an English template once the locale is `fr` (use a sentinel locale or the extraction check below).
5. **French file and extraction.** `tools/extract_strings.gd` scans `tr()` / `tr_n()` calls in `scripts/`, `addons/` and the `display_name` / text fields of `data/**/*.tres`, writes `locale/messages.pot` and merges new ids into `locale/fr.po` (existing translations kept, new ones empty). French translations written by me, reviewed by the owner. Test: every id found by the scan has a non-empty French entry; no obsolete entries.
6. **Check.** Render the hub, a battle and the settings in French (`--write-movie` with the locale set by an environment variable or a command line flag read by `Localization`); fix overflowing labels (longer French text).

### B. Camera follows a walking unit
7. **Follow target.** `CameraRig.follow(unit_view, path)`: eases the focus toward the unit along its path during `UnitView.play_move`, via the rig's existing move tween replaced by a per-frame lerp (frame-rate independent damping, `1 - exp(-k * delta)`); stops at once when the player pans (`dragged`, arrow keys). Skips when the whole path's cells project inside the visible area. A minimum glide time (0.4 s) and hold (0.3 s) for each new focus, so a run of quick enemy moves produces few glides. `EventPlayer` starts and stops it around `UnitMoved`; `BattleController` keeps the turn-start focus. Pattern: smooth damp camera follow. Test: the focus reaches the destination, a pan cancels it, a short on-screen move leaves the camera still, two consecutive moves give one glide.

### C. Effects tooling and polish
8. **Spell timing data.** `SpellData` gets `animation_scene` (optional model file whose animation is borrowed), `animation_start`, `animation_end`, `animation_speed` and `impact_delay`. `UnitModel.play_borrowed(scene, logical, start, end, speed)` merges the animation into the caster's `AnimationPlayer` library when bone names match (validation reports a mismatch). `EventPlayer` honors `impact_delay` between the cast and its effects, and a spell's optional `projectile` scene flies from caster to target (a tween on a `Node3D`, then the impact). Tests per field; the README's "Adding content" gets the new fields.
9. **Spell stage.** (Built as a runnable scene with a Design panel button rather than an editor tab; see the decision record.) Pick spell, caster and target `UnitData`; **Play** builds a flat 7 × 7 `BattleState` with the two units, casts through the real rules and plays the events through the real `EventPlayer` in a `SubViewport`; loop, speed slider and pause for timing; effect scenes reload on file save. Pattern: `EditorPlugin` bottom panel + `SubViewportContainer`, reusing the game's view classes under `@tool`. Test: playing a spell in the stage produces the same event list as the rules.
10. **Polish pass on the 15 spells.** Using the Spell stage: per-spell cast and impact effects, a projectile for ranged spells, timing per spell, screen shake on a hit above a share of max HP (camera offset noise, decaying), status auras (looping low-key particles per status carrier, removed on expiry). Renders to check; web budget kept (particle counts small).

### D. Audio
11. **Audio plumbing.** Buses `Music` and `Effects` under `Master` (created in code from a `default_bus_layout.tres`), `Audio` service on the `Game` root: `play_sfx(event_name)`, `play_music(track)` with cross-fade; sound sets are data (`data/audio/audio_set.tres`: event name → stream); volumes and mute in `Settings`, sliders in the settings screen. Web: audio starts after the title's Play press (user gesture); the mute and sliders persist.
12. **Shortlist.** I find CC0 candidates (OpenGameArt, Kenney, similar official pages), run the intake routine (scratch folder, type check, hashes) and put a sampler of the shortlist in `~/Documents` or play it in the game for the owner to choose by ear. Nothing is committed before the choice.
13. **Wire and credit.** Add the chosen files under `assets/audio/` with `SOURCE.md` (URLs, hashes), `CREDITS.md` rows and the settings credits; connect: UI clicks (screens), spell cast and impact (event player), footsteps (move), death, turn start, stingers (result screen), music per screen. Tests: the audio set covers every event name; volumes map to bus levels.

### E. Close
14. **Docs and review.** README (settings, new spell fields, Spell stage, locale and extraction commands), roadmap and backlog (6b done), `godot-code-review`, web build and publish only when the owner asks.

## Order and checks
A then B then C then D then E. After each task: `--check-only` on edited scripts, the whole test suite, `tools/fill_uid_refs.gd` after any `.tres` / `.tscn`, and an explicit-path commit. The editor re-saving `project.godot` (dropping the web `[rendering]` block) is checked before every commit.
